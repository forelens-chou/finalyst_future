# 中国国内期货行情数据采集系统 - 开发需求说明书 (REQUIREMENTS)

## 1. 项目背景与目标

### 1.1 背景
当前量化研究、策略回测与资产监控服务部署于境外服务器。由于地理位置与网络路由限制，境外 IP 访问中国国内主流金融行情源（如新浪财经、东方财富、各期货交易所接口）常遭遇 403 Forbidden、连接重置或严重限流。

### 1.2 目标
在 `fetchfu_db` 项目中，构建一套轻量、稳定、低维护成本的 Python 行情数据采集系统。系统能够通过国内代理通道，稳定抓取国内各大期货交易所（上期所 SHFE、大商所 DCE、郑商所 CZCE、中金所 CFFEX、广期所 GFEX）的主力连续合约及自定义合约的**日线（Daily）**与**小时线（60分钟）**数据，并持久化至 SQLite 数据库中。

---

## 2. 核心功能需求

### 2.1 数据源与标的覆盖范围
1. **数据源**：以开源金融数据库 **AkShare**（封装新浪期货、东方财富等主流公开行情通道）作为核心抓取引擎。
2. **标的覆盖**：
   - **默认主力连续合约**：覆盖国内五大交易所全品种的主力连续合约（如螺纹钢 `RB0`、铜 `CU0`、原油 `SC0`、豆粕 `M0`、PTA `TA0`、碳酸锂 `LC0`、沪深300股指 `IF0` 等）。
   - **自定义扩展标的**：支持在配置文件（`config.yaml`）中指定自定义关注品种或具体月份交割合约（如 `RB2410`）。

### 2.2 数据粒度与时间跨度
1. **数据粒度**：
   - **日线数据（1d）**：包含开、高、低、收、成交量、持仓量、结算价/成交额等核心字段。
   - **小时线数据（60m）**：标准的 60 分钟 K 线数据，覆盖日盘与夜盘各交易时段。
2. **时间跨度与更新策略**：
   - **固定历史跨度同步**：每次同步抓取近 1~2 年（可在配置文件中设定，例如 365~730 天）的历史数据。
   - **幂等覆盖（UPSERT）**：通过 SQLite 复合主键 `(symbol, datetime)` 进行 `INSERT OR REPLACE` 写入。每次拉取覆盖指定时间窗口，无需维护复杂的增量断点或游标，兼顾简单性与数据自愈能力（如历史数据修正）。

### 2.3 网络与海外 IP 穿透需求
1. **代理通道支持**：
   - 支持 HTTP、HTTPS 及 SOCKS5 代理协议。
   - 运行时自动注入代理环境变量或会话代理，确保境外服务器的所有对外抓取请求经由国内正向代理服务器转发，绕过国内服务商对境外 IP 的阻断与降频。
2. **代理自检功能**：
   - 提供独立命令行参数检测代理的连通性、出口 IP 所在地及响应延迟。

### 2.4 数据标准化与存储
1. **时区规范**：统一以中国标准时间（`Asia/Shanghai`, UTC+8）存储。
2. **时间格式**：
   - 日线时间：`YYYY-MM-DD`（如 `2026-11-20`）。
   - 小时线时间：`YYYY-MM-DD HH:MM:SS`（如 `2026-11-20 15:00:00`）。
3. **字段命名**：全小写蛇形命名（Snake Case），标准化输出：`symbol`, `datetime`, `open`, `high`, `low`, `close`, `volume`, `open_interest`, `turnover`。
4. **存储引擎**：本地单一 SQLite 数据库文件（`futures_data.db`），分设 `daily_bars` 与 `hourly_bars` 两张核心数据表。

### 2.5 执行与调度机制
1. **CLI 命令行操作**：
   - 提供清晰明了的命令行入口，支持全量抓取、按周期（日线/小时线）过滤、按指定品种（单一或多个）抓取。
2. **调度解耦**：
   - 系统不引入重型后台常驻调度守护进程，采用与 Linux 标准 `crontab` 结合的设计。
   - 针对国内期货交易时间（日盘 15:00 收盘，夜盘次日 02:30 收盘），提供标准化 cron 任务调度模板。

---

## 3. 非功能性需求

### 3.1 健壮性与防爬流控
1. **请求抖动与限频**：
   - 各品种抓取之间设置可配置的随机缓冲间隔（默认 0.5~1.5 秒），避免瞬时并发过高导致源站反爬封禁。
2. **自动重试机制**：
   - 针对偶发性网络抖动、DNS 解析超时或 HTTP 50x 错误，自动执行指数退避重试（重试 3 次，间隔 1s, 2s, 4s）。
3. **容错隔离**：
   - 单个品种或单次请求异常不阻断全局执行流程，跳过并记录错误，批次结束后汇总输出失败清单。

### 3.2 可观测性与日志
1. **双通道日志**：同时输出至控制台（终端友好）与滚动日志文件（`logs/fetchfu.log`，单文件 10MB，保留 5 个备份）。
2. **同步统计报告**：每次抓取任务结束时，输出执行耗时、总品种数、成功数、新增/更新记录数及失败品种明细。

### 3.3 交付物与依赖管理
1. **开发语言与依赖**：Python 3.12+，核心依赖控制在 `akshare`, `pyyaml`, `requests[socks]`, `urllib3` 等必要轻量库。
2. **生产文档**：包含需求文档、开发规格说明书、快速启动指南与 Crontab 定时配置示例。
